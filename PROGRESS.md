## Этап 02 (26.11.2026)

- `backend/app/rag/`: каталог 6 PDF, постраничное извлечение (pypdf + pdfplumber, выборочный OCR через Tesseract при наличии), SQLite FTS5, фильтр по `engine_model`.
- API: `GET /api/manuals/status`, `POST /api/manuals/search`, `GET /api/sources/evidence/{id}`, `GET /api/sources/pdf/{doc_id}`; health с `manuals_index`.
- UI: панель поиска по двигателю выбранной машины, цитаты, drawer с PDF.js (страница PDF 1-based).
- PDF только с диска `PDF_DIR=materials/manuals` (в Git не коммитятся); `scripts/sync_manuals.ps1`, `scripts/build_manual_index.py`, `scripts/verify_rag_queries.py`.

### Проверено

- Индекс: 6 документов, 1743 страницы, 73 «разреженные» страницы (<100 символов); OCR в этой сессии не потребовался (Tesseract не обязателен).
- `scripts/verify_rag_queries.py` — 8/8 (в т.ч. PDF 33–34 и **68** для моментов затяжки ЯМЗ-236М2, отказ при чужом двигателе/бессмысленном запросе).
- `pytest tests/test_stage02_rag.py`, `npm run build`.

### Ограничения (этап 02)

- Это поисковый слой, не LLM-агент: нет tool `search_manuals` у модели и Evidence Engine с ID-резолвом — этап 03.
- Качество на таблицах/битом текстовом слое ограничено; при слабой уверенности — честный `not_found`, страницу всё равно можно открыть в viewer.
- E2E drawer в браузере не записывался; API и скрипт верификации — основной контроль.
