# Требования хакатона и заказчика

Источник истины: ТЗ v6 от 16.11.2026 и реальные OpenAPI/заглушки; последние объявления организаторов от 24–25.11 и ответы брифинга от 26.11, приведённые в master. Новые официальные требования выше прежних FAQ.

## Формальный минимум ТЗ

| ID | Результат |
|---|---|
| F1 | Адаптивный веб-интерфейс с чатом |
| F2 | Выбор ТС и проверки, кнопка «Получить результат диагностики» вызывает POST /diagnose и выводит вердикт в чат |
| F3 | normal — продолжить штатную эксплуатацию при отсутствии иных признаков (не гарантия исправности); anomaly — тип, уверенность, риск и рекомендация; failed/bad — повторить запись, без диагноза и тикета |
| F4 | Ответ по руководствам конкретного двигателя, реальные document/page, честный отказ при отсутствии данных |
| F5 | Агент сам выбирает отдельные инструменты ML/RAG/ТОиР по контексту; не имитация жёсткой последовательности |
| F6 | URL обоих Mock API в окружении, заменяемость |
| F7 | Заявка с полями v6, после подтверждения отправляется в Mock ТОиР и получает ticket_id |

B1: история машины и заявок; B2: график anomaly_score по 3–5 проверкам; B3: главный механик, сводка «Норма / Требует внимания / Карантин (рекомендация)», приоритетный список, история по клику. Карантин только при обоснованной high-рекомендации по применимому источнику либо явно подтверждённом решении механика. Сбой записи требует внимания, не доказывает дефект. В ТЗ оценка 30 работоспособность +20 RAG +20 архитектура/код +15 UX +15 дополнения; отдельно действует общее Положение хакатона. Не обещать победу.

## Уточнения брифинга и решения

- Голосовой ввод высокоприоритетен. Достаточно запуска диагностики и общения с агентом; полный voice-control, озвучка не обязательны.
- Семь языков — выбранная реализация по пожеланию СНГ, узбекский и 1–2 индийских: ru, uz, kk, tg, ky, hi, bn. Не формальное перечисление из ТЗ.
- История короткая, поэтому только динамика и ранние предупреждения, не достоверный прогноз срока отказа.
- При низкой уверенности/помехах честно предупредить, осмотр и при необходимости новая запись. При наличии пригодного источника общий осмотр узла может быть достаточной работой в заявке. При отсутствии релевантной инструкции — рекомендация ручной дефектовки без заявки.
- Высокий приоритет отражает риски безопасности/эксплуатации и потенциальный дорогостоящий ущерб; не выдумывать цены и не принимать решение выпуска вместо человека. Логика приоритета команды, готовой таблицы заказчик не дал.
- Рисунки: лучше объяснить проверенную последовательность, при неразборчивости показать оригинал и ограничение. Запрещены выдуманные номера.
- Каталог запчастей и парсинг исключены; spare_parts остаётся в API. Нет фото автомобилей, реальной ML-модели, обработки аудио двигателя, 1С, внешних данных.
- Простота запуска и работоспособность важнее сверхсложной архитектуры и мутационных тестов.

## Сдача и сопровождение

Спринт 26.11 10:00–28.11 10:00 МСК. Вклад в продукт только в спринте; допускается ранее созданное универсальное с раскрытием. Публичный репозиторий с историей до 15.12. Оценивают последний коммит до дедлайна. Форма: описание сделанного/не сделанного, стек/модели/архитектура/запуск, URL стенда, видео ≤3 мин единым фрагментом (ускорение только ожидания), открытая ссылка на заполненный Excel. Один 3-минутный ролик, отдельный минутный не обязателен по брифингу. Сценарии С1 отклонение + источник + реальный TKT, С2 «Можно ли своим ходом перегнать машину на базу?» — ответ по источнику или честный отказ, С3 failed. С4 главный механик при готовности. Стенд доступен с момента сдачи до 03.12 23:59; до 15.12 возможно повторное включение в 24 часа по запросу. Питчи 1–3 декабря, живая демонстрация. +6 баллов возможны за выбор заказчика для пилота, не гарантия внедрения. См. [MASTER](MASTER.md) и [REGULATION](REGULATION.md).
