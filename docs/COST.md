# Учёт расходов GigaChat

| Этап | Источник измерений |
| --- | --- |
| Диагностика и подтверждение заявки | HTTP Mock ML и Mock ТОиР, без вызовов LLM |
| Индексация и поиск | Poppler или pypdf и SQLite FTS5. Embeddings и reranking отсутствуют. Ресурсы индексации учитываются отдельно |
| Выбор инструмента, подготовка черновика и ответ | Каждое завершённое обращение в `llm_usage_steps` и итоги по сессии в `llm_usage_by_check` |
| Голос | `llm_usage`, этап `voice_stt` |

`agent_total` в `llm_usage` агрегирует шаги агента. При едином тарифе используйте тарифицируемые `total_tokens`, из которых GigaChat уже вычел кешированные токены. При раздельном тарифе оплачиваемый вход равен `total_tokens − completion_tokens`, если договор следует этой схеме. Ответы без usage сверяйте с кабинетом. [Схема usage](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/post-chat)

Реальные расходы Ultra на полный сценарий **BLOCKED** до live-замеров с разрешённым корпусом. Документация указывает 50 млн токенов генерации Ultra на 12 месяцев для физлиц в Freemium. Для сравнения опубликованный тариф Max для юрлиц составляет 0,65 ₽ за 1000 токенов синхронной генерации, возможны минимальные платежи по договору. Голосовую ставку подтверждает владелец аккаунта. [Freemium](https://developers.sber.ru/docs/ru/gigachat/tariffs/individual-tariffs) · [Тарифы для юрлиц](https://developers.sber.ru/docs/ru/gigachat/tariffs/legal-tariffs)

| Период | Сценарии | Вопросы | Формула при измеренной средней цене одного сценария |
| --- | ---: | ---: | --- |
| Одна машина | 1 | 2–3 | Средняя цена |
| 14 дней | 50 | 100–150 | 50 × средняя цена |
| 30 дней в среднем | 107,14 | 214,29–321,43 | 50 × 30/14 × средняя цена |

Для замера используйте отдельную SQLite. Пройдите live-сценарии с двумя и тремя вопросами, поиском, ответом и черновиком. Снимите разницу по `llm_usage_by_check`, отдельно добавьте голос при его использовании. `scripts/export_usage_cost.py` агрегирует измерения из выделенной БД.

`GIGACHAT_MAX_TOKENS` ограничивает выход за шаг. `GIGACHAT_REQUEST_TOKENS` ограничивает резерв токенов на запрос со всеми шагами. `GIGACHAT_REQUEST_BUDGET_MICRORUB`, `GIGACHAT_DAILY_BUDGET_MICRORUB` и `GIGACHAT_MONTHLY_BUDGET_MICRORUB` задают денежные лимиты в микрорублях, периоды считаются по UTC. Ноль отключает лимит. Укажите ставки `GIGACHAT_CHAT_MICRORUB_PER_TOKEN` и `GIGACHAT_VOICE_MICRORUB_PER_TOKEN` по своему договору. При включённом денежном лимите операция без ставки блокируется. Нулевая ставка допустима для подтверждённого бесплатного пакета.

Резерв рассчитывается по размеру запроса с запасом и лимиту ответа. Для аудио используется `GIGACHAT_VOICE_RESERVE_TOKENS`. SQLite резервирует сумму атомарно до генерации. При 80% в журнале появляется предупреждение. Превышение даёт HTTP 429. Успешный ответ заменяет резерв фактическим `total_tokens`. Таймаут сохраняет резерв. Итоговые списания и предел счёта контролируются в кабинете провайдера.
