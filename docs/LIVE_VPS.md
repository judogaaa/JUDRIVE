# Изолированная LIVE-приёмка на VPS

Исходный релиз — `dfd55c3216df5d98e8e3c52caac59e63661dbfa2`. Исполнитель берёт точный SHA текущей чистой копии и проверяет на VPS, что он наследует этот релиз. Для запуска нужны Windows PowerShell 5.1 или выше, Windows OpenSSH и Git. На Ubuntu нужны Python 3.10+, Docker и Compose 2.24.4+ с поддержкой `!override`. Для автоматической проверки интерфейса на компьютере оператора нужны Node.js 22+ и npm.

## Запуск с Windows

Из каталога ветки `codex/live-vps-acceptance`:

```powershell
powershell.exe -NoProfile -File .\scripts\Invoke-JudriveLive.ps1 -AuditOnly
powershell.exe -NoProfile -File .\scripts\Invoke-JudriveLive.ps1 -ConfirmMock
```

При первом SSH-входе сравните отпечаток хоста с отпечатком из панели VPS. OpenSSH сам запрашивает пароль VPS. Чтобы создать и установить отдельный ключ, добавьте `-InstallSshKey`. Существующий ключ и записи `authorized_keys` сохраняются. При изменённом SSH-порте передайте `-SshPort`.

Исполнитель сначала показывает системный инвентарь и отпечатки материалов. Он использует проверенные файлы или архив на VPS и настроенный `JUDRIVE_MANUALS_URL`. Если источника нет, можно указать прямую разрешённую HTTPS-ссылку или путь к архиву. Параметр `-ArchivePath` позволяет указать разрешённый ZIP сразу, в том числе когда настроенная URL больше недоступна. Файлы копируются в приватный каталог только после проверки размера и SHA-256 по манифесту. PDF подключаются только для чтения.

Если ключ не настроен, исполнитель запрашивает его через `Read-Host -AsSecureString` и передаёт по SSH через stdin. Подтверждённый существующий scope сохраняется. Если его нет, возьмите scope из кабинета GigaChat. При необходимости передайте `-CaBundle C:\private\trusted-roots.pem` с доверенной цепочкой. TLS остаётся включённым. Файл `.env` с правами 0600 хранится внутри отдельного проекта.

При наличии разрешённого аудио передайте `-AudioPath C:\private\speech.wav` или выберите файл по приглашению. Запишите фразу «Проверка двигателя цифровым механиком». Тест требует распознавания ключевых слов. Пустой ввод оставляет STT **BLOCKED**. Подтверждение заявки выполняется только при `-ConfirmMock` и только через Mock ТОиР внутри созданного Compose-проекта. Пароль механика выводится один раз в консоли. Путь к отчёту появляется в начале работы, пароль и Authorization Key в отчёт не включаются.

## Изоляция и просмотр

Каждый прогон создаёт каталог под `/opt/judrive-live-acceptance`, уникальные образы, сеть и проект Compose. SQLite и RAG создаются в новом каталоге. Порт `18185` по умолчанию слушает только `127.0.0.1` VPS. Backend и Mock API доступны внутри сети проекта. Публичные данные автопарка для демороли включаются отдельным флагом `-AllowDemoFleet` после подтверждения разрешения на публикацию набора. Закрытые маршруты доступны только механику.

Повторный доступ из браузера через локальный туннель:

```powershell
powershell.exe -NoProfile -File .\scripts\Invoke-JudriveLive.ps1 -TunnelOnly
```

Откройте `http://127.0.0.1:18185`. Порт можно поменять флагами `-VpsPort` и `-LocalPort`. После завершения закройте туннель. Стенд остаётся в отдельном Compose-проекте, чтобы сохранить доказательства. Для остановки передайте последние 32 символа имени проекта, напечатанного как `project=judrive-live-…`. Данные и контейнеры сохраняются.

```powershell
powershell.exe -NoProfile -File .\scripts\Invoke-JudriveLive.ps1 -StopRunId <32-символьный-id>
```
План переключения production и отката применяется отдельно. [Развёртывание и восстановление](DEPLOY_HTTPS.md)

## Критерии результата

- Runner сначала проверяет оригиналы и конфликт РЭ 31 / РК 269 / РК 276. Затем выполняет OAuth, подбор реально доступной модели, ограниченный completion, валидатор функций, C1–C3, проверку ролей, историю, заявку и русскую речь.
- Сценарий C1 требует фактический след `search_manuals` и `prepare_defect_ticket`, ненулевой provider usage, применимый источник и подтверждённую запись в журнале. Шаги проверяются только на изолированных сервисах. Числа токенов smoke и сценариев выводятся раздельно. [Расходы](COST.md)
- Desktop и mobile проходят отдельный браузерный smoke по SSH-туннелю. При отсутствии локального Node.js, разрешённых материалов, ключа, речи или согласия на тестовую заявку соответствующая проверка остаётся **BLOCKED**.
