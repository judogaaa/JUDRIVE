# Матрица требований хакатона

Требования сверены с ТЗ v6, актуальными для проекта материалами брифинга и схемами Mock API в репозитории. [Требования](REQUIREMENTS.md) · [Финальный отчёт](FINAL_VERIFICATION.md)

| ID | Требование | Проверка в локальном контуре |
| --- | --- | --- |
| F1 | Адаптивный интерфейс и чат | Playwright проверяет основные экраны, телефонный viewport, темы и обработку ошибок |
| F2–F3 | Выбор ТС/сессии и реальный запрос к Mock ML, три вердикта | E2E и регресс сдачи проверяют вызов по паре идентификаторов, норму, аномалию, сбой записи и скрытие непригодных метрик |
| F4 | Поиск по применимому руководству, оригинальная страница и отказ при отсутствии источника | Тестовый корпус содержит физические страницы для сценариев RAG. Перепроверка с разрешёнными оригиналами остаётся BLOCKED |
| F5 | Отдельные инструменты диагностики, истории, RAG и черновика | Тесты исполняют инструменты и проверяют протокол GigaChat. Live-выбор модели остаётся BLOCKED |
| F6 | URL Mock API в окружении | pytest, Playwright и Compose поднимают исходные заглушки отдельно |
| F7 | Заявка в Mock ТОиР после согласия механика | Проверены исходная схема, применимость источника, повторная проверка ML и блокировка дублей |
| B1–B3 | История, график, кабинет главного механика | Проверены корректный контекст, фильтры и обоснованная рекомендация карантина. Рекомендация не изменяет фактический статус машины |
| UX | Голос, обучение, помощь и локализация | Проверены семь языков, редактирование транскрипции, мобильная навигация и голосовой транспорт через тестовый GigaChat. Нужна live-проверка распознавания |

## Сценарии сдачи

| Сценарий | Результат и ограничение |
| --- | --- |
| С1 · отклонение, источник и заявка | В локальном контуре создан номер TKT, заявка сохраняется после рестарта. Живой сценарий с оригиналами и GigaChat остаётся BLOCKED |
| С2 · «Можно ли своим ходом перегнать машину на базу?» | Проверен консервативный отказ при отсутствии прямого основания. Конфликт источников проверен на синтетических РЭ и РК |
| С3 · непригодная запись | Проверены предложение повторной записи, скрытие метрик и запрет оформления заявки |
| С4 · главный механик | Проверены история автомобиля, фильтры и отделение рекомендации от фактического карантина |

## Серверная применимость F-кодов

Модель берётся из карточки автомобиля. Для работ и деталей требуется применимый источник по узлу и комплектации.

| Коды | Условие допуска |
| --- | --- |
| F01–F07 | Семейства с применимым руководством, с проверкой узла и комплектации |
| F08 | Дизельные ЯМЗ-236М2 и ЯМЗ-536 |
| F09 | ЯМЗ-536. Для ЯМЗ-236М2 код наддува не подтверждён |
| F12–F13 | ЗМЗ-5234.10 и ЗМЗ-40904.10/40905.10 |
| F14 | ЗМЗ-40904.10/40905.10 с цепным приводом |
| F10–F11, неизвестная модель или код | Отказ при отсутствии подтверждения оснащения |

Высокий приоритет означает рекомендацию дефектовки до рейса. Решение о выпуске принимает механик.

Публичный URL, видео, расчёт и форма учитываются отдельно от локальных тестов. [Пакет сдачи](SUBMISSION.md)
