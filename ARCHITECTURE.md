# Архитектура JUDRIVE

## Сервисы

| Компонент | Ответственность |
| --- | --- |
| React, TypeScript и Vite | Рабочее место механика, автопарк, журнал, локализация и PDF.js |
| Caddy | TLS, раздача frontend, проксирование `/api` по внутренней сети |
| FastAPI | Сессии, валидация входа, диагностика, поиск и выполнение инструментов |
| Mock ML | Результат акустической проверки через `POST /diagnose` |
| Mock ТОиР | Создание подтверждённой заявки через `POST /tickets` |
| GigaChat | Генерация текста и выбор инструментов. Для голоса используется отдельная модель с поддержкой аудио |
| SQLite и FTS5 | Индекс руководств, журнал, диалоги, черновики и учёт расхода |

## Диагностика и источники

Автомобиль и сессия образуют проверяемую пару. Двигатель берётся из карточки автомобиля. При плохом сигнале или несовместимом результате сервер блокирует диагностический вывод и отправку заявки. Оценки ML отражают свойства модели и записи. [Спецификация и критерии](docs/MASTER.md)

Поиск ограничен применимыми источниками. Индекс хранит физические номера страниц, цитаты и версии корпуса. Backend проверяет идентификатор источника и применимость к заявленному двигателю при поиске, выдаче фрагмента и чтении PDF. При конфликте РЭ и РК ответ содержит обнаруженные формулировки и условия. [Подключение руководств](docs/SOURCES.md)

## Агент и заявки

Агент получает системные инструкции и историю диалога. Инструменты `get_diagnosis`, `get_vehicle_history`, `search_manuals` и `prepare_defect_ticket` выполняются на сервере. Для ответа с цитатой сервер проверяет источник. Для черновика он проверяет применимость результата, уверенность, состояние сигнала, работы, запасные части и ссылки. [GigaChat](docs/GIGACHAT.md)

Подтверждение связывает снимок черновика с машиной и сессией. Backend повторно проверяет диагностику, блокирует конкурирующую отправку и сохраняет итог внешнего вызова. Неизвестный исход вызова ТОиР требует сверки. Дашборд читает историю и журнал, включая рекомендации главного механика.

## Доступ и хранение

Браузер обращается к API через тот же origin. Кабинет механика использует подписанную HttpOnly-сессию, включённую только после настройки учётных данных. На HTTPS cookie имеет флаг Secure. Автопарк, диагностика, история, руководства, чат, голос и заявки требуют сессию. В контейнерах наружу опубликованы порты Caddy.

Разрешённый автопарк, PDF и CA монтируются только для чтения. SQLite находится на постоянном томе. Журнал отправок и индекс восстанавливаются из согласованного снимка SQLite. `/api/live` сообщает, что процесс отвечает. `/api/ready` проверяет зависимости и наличие настроенной модели в каталоге провайдера. [Эксплуатация](docs/DEPLOY_HTTPS.md)
